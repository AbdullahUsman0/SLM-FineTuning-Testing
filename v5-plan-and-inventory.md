## Predeclared data and selection protocol

1. Freeze scenario IDs and source-family-disjoint train/development/final assignment before training. Target 1,540 synthetic source scenarios across 11 contexts and approximately 6,000 total examples, prioritizing review over counts. All variants/turns/question examples from a source stay together. Existing v1–v3 are inventoried separately; no old or v4 paraphrases enter training without fact/leakage audit.
2. Generate exact canonical facts with verbatim evidence using the pinned fpy schema. About half of extraction examples should have 3–8 non-intent updates, with dense, correction, selected-answer and abstention groups. Report actual distribution, all unsupported slots and all deviations. Do not call automated checks human review.
3. Keep final labels outside tracked corpus and away from training/model-selection loaders under ignored `training-runs/v5-sealed/`. This is procedural sealing, not a cryptographic or independent external holdout. All final scenarios, uncertain records and a stratified training sample still need a human reviewer. Until that review, final evaluation is blocked and the corpus is a machine-validated candidate.
4. Use a versioned v5 prompt that lists the entire schema. The historical compact prompt limits to 24 active slots, excluding conditional first-turn facts such as `file_format`; changing only labels would preserve that mismatch. Preserve historical prompt behavior and reports rather than silently changing old experiments.
5. Pin HF base revision, tokenizer/chat template and fpy revision. Completion-only LoRA: r16/alpha32, dropout0.05, effective batch16, seed42, gradient checkpointing, cosine schedule, zero warmup, AdamW, clipping1.0. Measure token lengths without truncation. Pilot first. Default full run: LR5e-5 for2 epochs, keeping both epoch checkpoints. No sweep is authorized by a favorable test result.
6. Compare stock and each epoch adapter on the same development cases, same GPU, same non-quantized dtype, same v5 prompts and greedy decoding. Choose on exact non-intent micro F1 with no forbidden-inference increase and no material JSON/correction regression (predeclared tolerance: at most1 percentage point absolute). Ties choose lower latency then earlier epoch. Loss-best is not task-best. OpenAI uses pinned fpy's production provider and discloses prompt/decoder differences.
7. Preserve raw responses, strict schema/JSON failures, recovered-provider outputs where relevant, per-slot metrics, all-gold accuracy, correction/state behavior, forbidden updates, questions, latency and usage. Paired scenario-cluster bootstrap:10,000 resamples, seed42, percentile95% intervals; no resampling individual turns independently.
8. Freeze checkpoint, prompts, thresholds, input hashes and implementation revision in a dated selection manifest before a once-only final run.
