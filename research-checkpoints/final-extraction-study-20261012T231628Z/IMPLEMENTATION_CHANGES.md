# Material changes and reasons

All new work is isolated in this timestamped checkpoint and a private evaluation directory. Historical policy files, adapters, reports, datasets and result ZIPs remain byte unchanged.

1. Recorded environment and verified pinned sources/model identities before inference. The runtime imports the verified r8 bundle and fpy snapshot, rather than an unrelated current application checkout.
2. Composed the frozen structural `ComparisonPolicy` with a new exact-evidence gate. Old manual chat admitted a narrower candidate representation than benchmark parsing; the new manual and benchmark use one shared implementation. Historical scores retain their original policy.
3. Preserved one-pass candidate decoding, including explicitly encoded strings such as numeric-looking identifiers. Converting the admitted result to a Pydantic model does not decode again. Added contract and cross-provider tests.
4. Specified target-text boundaries, filename-inference status, correction/confirmation behavior, unknown intent and ambiguous cadence in a versioned annotation rubric. Retained the full 79-slot schema.
5. Implemented semantic state snapshots using the historical serializer so datetime values are JSON-safe. Separate raw metadata retention avoids claiming empty updates guarantee complete state preservation.
6. Kept the deterministic evaluation generator private: publishing it could expose proposed labels even if the JSONL itself were excluded. Candidate 1 is preserved privately; candidate 2 reduces repeated normalized turns from 630 to 81. Revision was based on offline design review, not model scores. Twelve template groups and cross-group generic clauses remain explicit limitations.
7. Used explicit allowlists for overlap screening against accessible training/development inputs; no sealed final labels were opened. Prepared pending review materials without fabricated human decisions.
8. Fixed an adapter-path type before smoke inference: the loader requires `Path`, not a string. Recorded the actual BF16-base/FP32-LoRA behavior and verified all parameters on CUDA. Both adapters use the same loader. The failed launch remains preserved separately.
9. Added immutable raw/score receipts, call/context/gold identity checks, pre-request spending reservations and crash recovery. The journal identity includes the run UUID, preventing unrelated new runs from sharing a cache identity. Resumed scoring retains the original generation latency instead of timing offline replay. Semantic failures receive no retry; transport retries remain bounded. Offline fixtures test interruption after raw persistence, component/rollout reconstruction and no repeated completed calls.
10. Prepared a grouped alternating local schedule and independent verifier. Final cohort scoring is gated on actual review, budget and complete registration; neither paid execution nor the pinned hosted snapshot was tested in this new study.
11. Installed tiktoken 0.12.0 only in an isolated private token-counting directory for preflight. The working GPU environment was not upgraded. The prior budget estimate remains an unapproved historical planning artifact.
12. Applied the latest user decision: use existing verified results with **$0 new paid budget**. Registration, matched scoring and hosted-provider construction/generation now fail closed on deferred or missing decisions. Added tests demonstrating failure before source/model/API work.
13. Reproduced historical scores under original scoring, added explicit cohort IDs, and wrote paper/supervisor/handoff documents. Corrected the language attribution of one component missing-brace failure based on raw record metadata; did not alter raw responses or historical metrics.

`TEST_RECEIPT.json`, `policy/freeze-manifest.json`, `PREPARATION_COMPLETION.json` and the offline ZIP's file manifest record the final verification/publication state. They certify offline preparation, not completed independent human annotation or final behavioral evaluation.
