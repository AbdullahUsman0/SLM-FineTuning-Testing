## Implementation finding fixed during this audit

The Colab preflight cell called `verify-corpus-v5.py --corpus`, but the committed CLI required `--output` and `--sealed-output`. A fresh Colab clone cannot contain the ignored sealed final directory by design, so the cell would fail before the pilot.

The verifier now supports two explicit levels:

- `--output <public corpus>` verifies the manifest, every tracked public file, development scenarios/SFT reconstruction, split coverage, smoke membership, and full-input deduplication. It reports that sealed hashes were not verified.
- Adding `--sealed-output <local sealed root>` retains the stronger local byte-hash check without parsing labels.

The notebook now uses the public-only command, a regression test asserts the exact CLI, the suite passes 156 tests, and both public-only and full local verification pass.

## Data review and leakage interpretation

The 638-scenario review queue comprises 346 train, 61 validation, and all 231 final scenarios. Its reasons are 462 context-dependent/uncertain examples, 231 final-review requirements, and 60 stratified train samples; reasons can overlap.

The 6,663 cross-split overlap flags break down as:

| Flag class | Count |
| --- | ---: |
| Structural-only template similarity | 5,037 |
| Text Jaccard 0.72–0.8999 | 1,050 |
| Text Jaccard 0.90–0.9999 | 4 |
| Text Jaccard 1.0 on the representative utterance | 572 |

The generator reuses the same index-controlled facts and correction wording across domains, so some train/validation representatives differ only through prior context or domain facts. Full prompt+state input deduplication still reports zero duplicates, and the final split uses the held-out `heldout_handover` template family with the entire synthetic-health domain held out. This is a useful controlled synthetic benchmark, but it does not demonstrate linguistic independence or real-world generalization.

Reviewers should not click through 5,037 identical structural-family warnings individually. Before full training, they should:

1. Review every validation scenario and all 231 final scenarios for label semantics, naturalness, evidence, state transitions, and question relevance; the final reviewer must remain independent from model selection.
2. Review the 346 queued training scenarios and a cluster-level sample of overlap flags, grouping identical `(category, slot-set, template family)` patterns. Record cluster decisions and the number of covered pairs.
3. Reject recurring defects at the template/category level. If any recurring defect or unacceptable train/validation lexical cloning is found, create immutable `v5-...-r2`; do not edit r1 or its sealed final files.
4. Describe r1 as synthetic/template-generated and report held-out-domain/template subgroups separately. Do not claim zero leakage.

An actual human must sign the review artifact. Automated validation or this Codex audit is not human approval.
